# 拾荒机 · Automatic Collector

饥荒联机版（DST）服务器模组。原创木制小车逐个拾取、采摘和收获，把可合并的同类产物凑成一组，再走到附近箱子卸货。它没有可打开的储物界面，也不替代箱子。

当前版本 **0.4.0**：模型仅保留车身和贴图自带的车轮，移除夹子、盖子、货包和叠加轮子；拾取采用靠近物品后下沉，采集复用已确认的冲撞动作，装箱轻微点头。集中采集、集中运输规则保留。更新时替换原模组文件夹中的运行文件，保持文件夹名 `automatic_collector`；退出并重新启动游戏以重新加载资源。不要同时启用新旧两个副本。

## 安装与使用

1. 将生成的 `publish/` 目录内全部内容复制到 DST 的 `mods/automatic_collector/`，无需解压。该模组文件夹内应直接包含 `modinfo.lua`、`modmain.lua`、`anim`、`images` 和 `scripts`，不要再套一层 `publish` 文件夹。
2. 在创建世界的**服务器模组**中启用“拾荒机 · Automatic Collector”。所有客户端均需要启用该模组；同时支持地上和洞穴分片。
3. 在炼金引擎旁解锁配方：**木板 × 2、石砖 × 2、齿轮 × 1**。可在科学/建筑筛选中查找“拾荒机”。
4. 将它从背包放到地上，放下的位置就是工作中心。默认半径为 12 个世界单位，约 3 块地皮。
5. 在工作范围内放置箱子。优先送到已有同类物品且装得下整份货物的箱子，其次使用其他可接收的箱子。右键暂停或启动。
6. 左键捡起后重新放下，可以移动工作中心。携带中的货物会交还拾取者；背包放不下时使用原版落地逻辑。

## 作业规则

- 拾取地上的普通物品；采摘成熟的草、树枝、浆果等 `pickable` 资源；收获成熟农田作物以及使用 `crop` 组件的旧式作物。
- 巨大作物先通过原版采摘逻辑落地，再逐次冲撞打开，最后分别拾取蔬菜和种子并合并同类货物运输。每次冲撞仅执行一次原版工作量。不会自动敲建筑、挖植株、砍树、浇水、照料或播种。
- 每次动作只作用于一个目标。小车移动时轻微晃动，拾取时到达掉落物中心附近（0.15 世界单位）后下沉，.5 秒时交互；采摘/收获复用冲撞，.7 秒时交互；装箱只做轻微点头，.5 秒时交互。货物保留在内部运输槽，不再额外绘制货包。前、后、左右视图由原版四面朝向系统选择；左右共用侧面动画，由引擎镜像，支持 Q/E 转动镜头。
- 默认只携带一组：逐个拾取可合并掉落物，并继续采摘/收获同类产物，达到该物品的原版/模组堆叠上限后运输。掉落物优先，再选择合适植株；范围内没有更多安全、可用且可合并的目标时，未满组也立即运输，不等待新目标。
- 采集不拆分一株的产量。下一株的整份主产物超过当前组余量或箱子余量时，先卸货再继续采集；动作接触时再次检查。普通农田蔬菜、草、树枝、浆果和旧式成熟作物均可按已知主产物继续凑组。未知动态产物、无法预判的皮肤/自定义堆叠限制先卸货，再空载采集。
- 合并遵循原版 `CanStackWith`，包括皮肤和第三方规则。只差少量就满组时仅拆取目标所需数量，其余留在原处。箱子容量限制累计数量，避免合并到无法卸货；动作接触时再次检查容量。
- 箱子不在范围内、满了、被打开、被限制或不接收货物时，换其他可用箱子。已携带货物无处可送时保留货物并停止采集，等待重新有容量。
- 默认只有一个内部运输槽；不会主动用临时手持槽装第二组。采摘/收获产生额外种子或溢出产物时，临时手持槽中的物品通过原版掉落逻辑留在地上，继续集中收集当前组，之后分组拾取余下产物。容量升级后优先使用可用运输槽。内部物品随存档保存。
- 工作区域固定在放置中心；拾取和敲击额外留出 2 个世界单位，覆盖采收掉落物的散落位置。箱子和新采摘目标始终限制在配置半径内。
- 多台拾荒机会占用各自的目标。失败目标暂避 10 秒，单次任务最长 20 秒，避免卡死或重复尝试同一路径。
- 不拿陷阱诱饵、活物、不可替代物品、诅咒物、背包/容器和普通重物。保留打蜡巨大作物。带 `ac_ignore` 标签的实体可明确排除。
- 无玩家在附近导致实体休眠时停止工作，不模拟离线瞬间采集。船上仅处理同一平台上的目标，工作中心跟随船移动，不跨船或跨海。
- 不消耗燃料，不参加战斗。暂停后仍可捡起和搬动。

## 配置

| 配置 | 默认 | 可选值 |
| --- | --- | --- |
| 工作半径 | 12 | 8 / 12 / 16 |
| 运输规则 | 优先同类，也用空箱 | 仅已有同类物品的箱子 |
| 自动采摘与收获 | 开启 | 开启 / 关闭 |
| 敲开巨大作物 | 开启 | 开启 / 关闭 |

“仅同类箱子”模式需先放入一个样品。未知产物的第三方资源会保守地跳过；可通过适配器扩展。普通模式对采摘产物做预判，对实际货物再次运行容器容量和物品过滤检查；第三方回调产生无法预测的产物时可能停工等待接收容器。

## 兼容与升级

仅添加独立 prefab、组件、Brain、StateGraph 和命名动作，不替换原版组件或原版动作。标准 `inventoryitem`、`pickable`、`crop` 和 `container` 模组资源通常可直接使用；角色限定或自定义回调需要适配并实际测试，不能保证所有第三方模组无条件兼容。

升级注册、持久化、移动速度、动作速度、运输槽位和预留 Light 已具备接口，**当前版本没有升级物品或升级配方**。容量接口可供后续升级启用多组不同物品运输；默认仍是一组。详见 [扩展接口](docs/API.md)。

## 开发与验证

Python 仅用于美术构建和测试，不是玩家运行依赖。安装 `uv` 后：

```powershell
$env:UV_CACHE_DIR = Join-Path (Get-Location) '.cache/uv'
uv sync
uv run pytest -q
uv run ruff check tools tests
uv run ruff format --check tools tests
uv run ty check tools tests
uv run tools/build_assets.py --mod-tools "D:/Programs/Steam/steamapps/common/Don't Starve Mod Tools/mod_tools"
uv run tools/publish.py
```

发行文件直接输出至 `publish/`，不压缩、不生成 `dist/`。每次运行发行脚本会先检查源文件，再清空 `publish/` 中的旧内容并重新复制；不要在该目录保存手动修改或其他文件。将其内容复制到游戏的 `mods/automatic_collector/` 即可。原始美术、可编辑动画及构建/测试工具保留在本项目中，不需要安装进游戏。

构建只需官方 Mod Tools 的 `TextureConverter.exe`。已提供可直接使用的编译资源。原创零件位于 `assets/source`；骨骼、动画曲线和导出逻辑在 `tools/build_assets.py`；可编辑 Spriter 源、动画 GIF 和预览图在 `assets/generated`。详见 [美术制作说明](docs/ART.md) 与 [测试记录和实机检查](docs/TESTING.md)。

发行脚本按白名单复制模组入口、图标、许可证、README、`scripts/`、`anim/` 和 `images/`。`docs/` 仅保留在源码仓库，不复制到 `publish/`；上述扩展、美术和测试文档链接供源码仓库阅读。发行目录不包含测试世界、本地游戏脚本、缓存或开发环境。`anim/` 中的 ZIP 是游戏必需的已编译动画资源，会原样复制。当前 Git 分支为 `feature/automatic-collector`，默认不创建提交。
