# 寻路性能约束与待改进问题

更新日期：2026-10-09。适用基线：0.7.6。这里记录已影响使用、但尚未通过增加计算量直接解决的问题。写入文档不代表行为正确，也不免除后续修复；已确认的任务超时缺陷与计算预算限制分别处理。原始场景和对照见 [复杂路况测试报告](NAVIGATION_STRESS_076.md)。

## 1. 可达路线因节点上限被判定不可达

- **状态：已复现，待改进。** 单次搜索最多展开 4096 个节点。粗网格、细网格和几何间隙点共享这个上限，搜索额度耗尽后当前返回 `unreachable`，没有区分“已证明无路”和“尚未找到路”。
- **影响：** 大面积连续折返布局中，小车会保货等待并重试；地图不变时，重复搜索可能每次都在相同位置耗尽额度。7 道交错墙的 8 组旋转/移动模式组合均复现，独立几何检查确认存在合法参考路线。
- **对照：** 20×24 折返布局约 5.07 秒模拟时间返回不可达；仅在测试内存中把上限改为 12000，便能算出约 262.01 单位路线并到达。该对照证明当前搜索不完备，不代表提高上限后开销可以接受。
- **可重建的布局参数：** 工作中心 `(13, 0)`、半径 20；起点 `(-1, -9.5)`，箱子 `(25, -9.5)`。在 x=0、2、…、24 放半径 .45 的圆体墙，z 间隔 .75；墙的序号从 0 起，偶数序号墙的 z 范围为 -10～8，奇数序号为 -8～10。可通行地形限制为 x∈[-2,26]、z∈[-10.5,10.5]，墙体交替在两端留口。对照须关闭测试中的总时限或使用修复后的进展计时，否则长路也会触发另一种取消原因。
- **暂不直接提高上限的原因：** 提高上限会增加复杂和真正不可达目标的搜索总工作量、队列长度及内存占用。多车共用预算时，其他车辆也会等待更久；解除每帧限制又可能将开销集中到服务器单帧。
- **后续方向：** 区分预算耗尽与确定不可达；评估保留搜索进度、分层路径或先求通道骨架，再细化局部的方案。不能只用更大的常量让一个夹具通过。
- **验收：** 保留现有单帧预算，在固定种子、不同起点/旋转和多车条件下验证可达率、总展开量、队列等待、内存及真正封路时的退避；最终需要实机负载数据。

## 2. 多车和复杂地图下仍存在较长规划等待

- **状态：已测量，等待时间待优化。** 每世界每帧最多 128 工作单位，每轮最多 16 单位；初始、完成及复查快照的异步查询合计每帧最多启动 4 次。它们限制计算峰值，同时让多车竞争更长时间。
- **证据：** 互不拥堵的独立障碍区内，单车约 2.60 秒完成规划，8 车共同搜索需约 20.57～20.83 秒。100 组扩展诊断中的森林、迷宫和交错墙也显示规划等待随车辆数增加。
- **本轮修复后复验：** 32 车共享规划的森林、迷宫、交错墙分别需约 62.23 / 70.90 / 53.83 秒模拟时间，最后排队车辆均能继续送达。这说明任务不再因旧总期限反复归零，但较长等待仍真实存在；这些压力夹具不能用于估算实机帧率。
- **与超时缺陷的区别：** 固定 20 秒总期限会把仍有进展的任务反复归零，属于需要修复的生命周期错误；修好计时后，实际计算与排队时间仍然存在。
- **暂不直接扩大预算的原因：** 更多单帧计算可能使服务器卡顿，不能用夹具模拟秒数宣称实机流畅度提升。
- **后续方向与验收：** 评估更高效的搜索顺序、可安全复用的地形/静态障碍信息和并发调度；同时报告最早/最晚完成时间与单帧开销，不能只展示平均值。真实物理推挤另需实机验证。

## 3. 密集实体下的安全复查会限制恢复移动

- **状态：设计边界与已有停车行为；极端密度的实机影响未量化。** 路线快照超过 .5 秒未更新时停车，复查每帧最多启动一份、最多使用共享预算的一半；单份快照的返回列表可以跨帧处理。大量实体或车辆会增加复查等待，构建完即已过期的快照也不能恢复行走。
- **暂不放宽的原因：** 直接延长过期阈值或允许带着过期快照行驶，会推迟对新墙体、地形或目标位置变化的响应；直接提高复查配额又会挤占搜索预算。
- **另一个边界：** 引擎单次 `FindEntities` / `Pathfinder:IsClear` 调用不可由 Lua 拆分，现有预算只能限制启动次数与调用之间的处理，不能提供硬性的毫秒上限。本轮没有把这一点当作已经测得的实机卡顿缺陷。
- **后续方向与验收：** 评估局部增量快照、与路线相关的查询范围及复查优先级；验证新障碍能及时阻止通行、过期快照不会恢复移动、取消与船体生命周期正确，并测量真实服务器开销。

## 本轮单独处理的确认缺陷

“共享排队超过总期限导致反复清空搜索”和“有效行驶超时后整组丢货”不作为性能原因暂缓项。本轮改为按搜索/移动进展续期、工作动画独立计时，并区分导航阶段超时与交互超时。保持上述节点、每帧工作量与快照限制；新增 14 项正式回归确认 8 车全部实际配送、长路线继续完成、停滞仍能取消、导航受阻保货和交互失败独立处理，全量 469 项通过。详细结果见 [验证记录](TESTING.md)。
