# 拾荒机技术报告

适用版本：0.4.1。本文记录实现约束与设计依据；构建和发行操作见 [开发者指南](DEVELOPMENT.md)，玩家说明见 [README](../README.md)。

## 架构与执行边界

作业仅在 master simulation 执行。模组添加独立 prefab、组件、Brain、StateGraph 和命名动作，不替换原版组件或全局动作，也不给小车增加可打开的储物容器。

| 模块 | 职责 |
| --- | --- |
| `modmain.lua` | 注册配方、配置、命名动作与扩展 API |
| `prefabs/automatic_collector.lua` | 网络实体、组件、显示状态和拾取/放置生命周期 |
| `ac_targets.lua` | 安全筛选、目标占用、产物预判与容器容量查询 |
| `components/ac_worker.lua` | 任务选择、接触时验证、货物合并、取消和存档 |
| `brains/ac_collectorbrain.lua` | 空闲时选择一个任务，忙碌时等待 |
| `stategraphs/SGac_collector.lua` | 面向目标、动作播放、交互时刻与退出清理 |
| `components/ac_upgradable.lua`、`ac_api.lua` | 升级等级与适配器注册 |

上述脚本模块路径均相对于 `scripts/`。每个任务只针对一个实体，动画接触时重新验证；不在一个动作中同时交互范围内所有目标。

## 集中采集与集中运输

默认一个原版 `inventory` 运输槽，货物随原版库存存档保存。选择任务时优先拾取可合并掉落物，再继续采摘或收获已知同类产物；满组或没有更多合适目标时运输，不等待新目标出现。

拾取数量同时受运输槽余量、物品自身堆叠上限和接收箱子的总容量约束。合并使用原版 `CanStackWith`，保留皮肤与第三方规则。接触时只拆取当前目标所需数量，再执行原版 `PICKUP`；例如上限 40、已携带 39、地面有 7 时，只取 1，剩余 6 留在原地。

采集预判只查询主产物和单次产量，不生成预览物品，不调用采集或随机掉落回调。下一株整份主产物放不下时先卸货，接触时再次检查箱子容量。标准农田植物、`pickable` 与成熟 `crop` 支持已知产物续采；未知动态产物、皮肤或自定义堆叠限制无法可靠预判时，先卸货再空载采集。

不主动用临时手持槽增加第二组容量。采集产生额外种子或溢出产物时，经原版 `DropItem` 留在地上，之后分组拾取。巨大作物先通过原版采摘落地，再逐次执行一次原版工作量，最后按产物分组运输；不处理打蜡巨大作物或普通建筑。

## 容器与空间限制

容器必须在配置半径内、位于同一平台、可打开、非只读、未被其他实体打开，并满足角色限制及原版物品过滤和 `CanAcceptCount`。默认配置为仅已有同类物品的箱子；允许空箱模式仍优先已有同类物品的接收容器。无处卸货时保留货物、停止采集并等待。

工作中心固定在放置位置。拾取与敲击额外允许 2 个世界单位，覆盖掉落物散落位置；箱子与新采摘目标仍限制在配置半径内。船上中心跟随平台移动，只处理同一平台，不跨船或跨海。实体休眠时取消任务，不模拟离线瞬间采集。

目标占用用于避免多机重复选择同一资源。失败目标暂避 10 秒，任务超时为 20 秒；暂停、捡起、重新放置和休眠走取消与清理流程。选择目标和接触时均检查实体有效性、工作状态及可交互条件。

## 动作时序与关箱生命周期

下表为默认速度；动作升级同时调整播放倍率与交互、结束时刻。

| 状态 | 动画 | 总时长 | 接触时刻 |
| --- | --- | --- | --- |
| 拾取 | `pickup` | 1 秒 | .5 秒 |
| 采摘 / 收获 | `hammer` | 1.3 秒 | .7 秒 |
| 敲巨大作物 | `hammer` | 1.3 秒 | .7 秒 |
| 装箱 | `store` | 1 秒 | 第 6 帧，.2 秒 |

拾取只为本模组的 BufferedAction 设置 `.15` 世界单位的到达距离，实体靠近掉落物后车身下沉；不修改全局 PICKUP。冲撞和下沉只改变动画图层，实际位移由原版 locomotor 完成。状态进入时面向目标，四面朝向由引擎结合镜头选择，支持 Q/E 转动。

装箱参考原版 `SGstorage_robot`：第 6 帧执行原版 `STORE`，由原版动作打开容器；成功回调释放任务，但保持箱子开启到装箱状态退出。小车默认动画长 1 秒，故开启持续约 .8 秒；原版动画总长度不同，未强制延长小车动画。

任务完成后状态仍带 `busy`，Brain 不启动下一次作业。失败、非动画存放及时关箱；正常完成、暂停或其他状态中断由退出回调清理。关闭的是小车自身的容器开启关系，保留其他开启者。动作只能在接触时执行一次，失败不会直接改变货物数量。

## 美术、兼容与扩展

模型只包含三张原创车身贴图及贴图自带的车轮，没有夹子、盖子、独立轮子或货包。三视图导出 21 段动画、585 帧，每帧一个车身元素；侧面掩码 `5` 由引擎镜像，避免重复左侧动画。绑定、曲线和编译格式见 [美术说明](ART.md)。

标准 `inventoryitem`、`pickable`、`crop` 与 `container` 通常可复用；角色专属字段、定制采摘回调、未知产物与非标准容器需适配并测试，不能保证所有第三方组合兼容。实体标签 `ac_ignore` 排除采集，`ac_no_delivery` 排除卸货，`ac_delivery_container` 允许符合安全条件的其他容器类型。

升级预留移动速度、动作速度、Light、等级持久化与 `1..8` 运输槽接口，当前没有实际升级物品或配方。降低容量不得截断已有货物；未知升级等级保留以便扩展恢复。适配器提供纯查询的匹配、动作与主产物描述，详情及示例见 [扩展接口](API.md)。
