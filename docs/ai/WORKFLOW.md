# AI 协作规范

与根目录 [AGENTS.md](../../AGENTS.md) 一起使用。玩家使用方式以 [README](../../README.md) 为准，工具操作和当前实现以 [开发者文档](../developer/README.md) 为准。

## 开始与范围

- 检查当前分支、工作树和暂存区，保留用户已有修改。仅修改当前任务需要的内容。
- 不直接在 `main`/`master` 开发，新分支默认使用 `codex/<主题>`。默认不创建提交；用户要求提交时只包含授权范围，采用 Conventional Commits。
- 始终使用中文沟通；commit message 的标题和正文，以及 PR 的标题、描述和评论，均使用英文。
- 未经用户或适用指令明确要求，不派子代理。历史记录中曾经使用子代理，不构成当前任务的授权。
- 游戏测试由用户负责；未经明确要求，不启动客户端或专用服务器。历史服务器复现命令的存在也不构成启动授权。

## 实现与资源

- 作业仅在 master simulation 执行。每次动作只交互一个目标，动画接触时重新验证；使用原版组件接口，保持数量、属性和存档状态，避免替换原版全局行为。
- 项目使用 Python 3.12+ 与 `uv`。命令和环境要求集中维护在 [开发者指南](../developer/DEVELOPMENT.md)，不要在多个说明文件复制一套工具流程。
- Lua 使用四空格缩进并兼容 Lua 5.1/LuaJIT；局部变量用 `snake_case`，组件方法用 `PascalCase`，自定义组件与动作用 `ac_`、`AC_` 前缀。Python 使用四空格、100 字符行宽，并遵循 Ruff 与 ty 检查。
- 美术修改落在 `assets/source/` 的源图、绑定或 `tools/build_assets.py` 的运动曲线，再重新构建。`assets/generated/` 与 SCML 会被覆盖，不能当作修改入口。
- 四面实体共用侧面动画，由引擎镜像；不再导出预镜像左侧。图像生成的输入和提示词见 [美术生成说明](ART_GENERATION.md)。
- `.reference/`、`.runtime/`、`asset_work/`、缓存和 `publish/` 不作为源码提交。不分发游戏或工坊参考资源、测试存档与缓存。
- 发行只通过 `tools/publish.py` 的白名单生成固定的 `publish/`；不要手动修改输出。`docs/` 不发行，游戏必需的动画 ZIP 原样复制。
- `modinfo.lua` 的 `description` 只修改版本号，不主动修改文案内容。

## 验证与交付

行为修复覆盖相关边界，尤其堆叠、容量变化、目标抢占、存档恢复和动画接触时刻。测试文件使用 `test_*.py`，函数使用 `test_*`，Lua 场景使用描述性 `snake_case`；没有固定覆盖率门槛。覆盖范围和依赖见 [测试指南](../developer/TESTING.md)。

修改后执行与范围相符的检查，说明无法执行的项目与原因。纯文档整理检查链接、路径与差异；资源或代码变化时运行对应构建及回归。离线预览不是游戏截图，离线成功和历史实机成功都不能证明当前客户端通过。

按 [写作规范](WRITING.md) 同步相关文档。用户可见行为、配置或 API 变化时更新玩家说明和开发者专题；模组版本变更时同步 `modinfo.lua`、工具项目、锁文件与 README，文档整理不单独提升版本。

最终回复简要说明变更文件、验证结果、文档情况、Git 分支与提交状态，以及未完成事项或风险。需要长期保留的执行过程、诊断结果或交接内容写入 `history/`，不要混入玩家说明和开发步骤。
