# AI 文档写作规范

写文档前先确定读者和用途，再按 [文档索引](../README.md) 选择维护位置。内容以当前源码、配置和可核对的验证证据为依据。

## 按读者写

| 读者 | 主文档 | 应写内容 |
| --- | --- | --- |
| 玩家 | 根目录 README、`docs/user/` | 如何制作、使用、配置和排查；可观察的效果、限制与验收操作 |
| 开发者 | `docs/developer/` | 当前架构、接口契约、资源规格、可重复运行的命令、测试边界与已知问题 |
| AI | AGENTS.md、`docs/ai/` | 工作和写作规则、生成提示词、任务过程、阶段计划、验证证据与交接上下文 |

玩家说明不加入代理分工、提示词、工作分支、临时脚本或本轮交付过程。根目录 README 必须独立可读，发行中不包含 `docs/`，因此不链接仅存在于源码仓库的相对文档。

开发者文档使用稳定、可复现的描述。将“本轮已完成”“用户确认”“下一步由用户测试”等任务叙述放到历史记录；当前实现的真实限制和未验证范围仍须在开发文档说明。开发手册提供自己的编码与提交约定，不要求人类开发者先读 AI 指令。

AGENTS.md 保留关键约束和阅读入口。详细协作流程、写作规则及生成记录放在 AI 目录，避免在多个文件重复维护完整说明。

## 当前说明与历史证据

- 当前说明直接描述生效的行为与接口；旧方案与实际代码不一致时更新当前文档，历史方案按当时状态归档。
- 历史记录标注日期、版本或被测提交、运行命令、结果及未覆盖范围。已有记录的测试数量、耗时、文件数和日志不得改成未经执行的新结果。
- 记录环境差异：原版源码契约、离线夹具、离线动画、客户端与专用服务器验证各自说明范围。模拟秒数、调用次数和离线成功数量不能换算为实机帧率或联网验证结论。
- 缓存中的诊断脚本和结果注明本机依赖，不写成新克隆仓库即可执行的标准流程。能长期复用的测试方法放到开发者测试指南，原执行过程归档到 `history/`。
- 同一规则或事实在主文档维护，其他文档用链接引用；调整目录时同步相对链接、图片路径、锚点及入口索引。

## 语言与同步

文档和沟通使用中文，代码、命令、配置、日志与错误可保留原文。commit message 的标题和正文，以及 PR 的标题、描述和评论，均使用英文。

玩家可见功能、配置或操作变化时更新 README；实现、接口、美术、声音和测试方法分别更新开发者专题。AI 写作或协作规则变化时更新 AI 文档。没有对应内容变化时，不为完成一轮任务而改写无关文档。

`modinfo.lua` 的 `description` 仅修改版本号，不主动改文案。版本变化须同步工具项目与锁文件；文档整理不提升模组版本。修改后检查文档链接和差异，交付时区分本次检查与历史记录。
